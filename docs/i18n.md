# Mehrsprachigkeit

Deutsch bleibt Quellsprache und liegt unverändert unter `/`. Jede weitere Sprache liegt unter `/<code>/` (z. B. `/en/projects/`). Es gibt zwei Root-Layouts (`app/(de)` und `app/[lang]`), damit `<html lang>` und `dir` stimmen; die 404-Seite ist `app/global-not-found.tsx` (Next-Flag `experimental.globalNotFound`).

## Drei Ebenen

1. **Englisch, von Hand geschrieben:** `src/i18n/dictionaries/en.json` und `content/en/projects/*.md`.
2. **Vorab übersetzte Sprachen (Skript und täglicher Workflow):** `node artifacts/jonas-website/scripts/translate.mjs` übersetzt `de.json` und die Inhalte per Claude API (Key nur als Umgebungsvariable `ANTHROPIC_API_KEY`). Ergebnis sind `src/i18n/dictionaries/<code>.json` und `content/<code>/...`, die eingecheckt werden. Eine Sprache erscheint auf der Seite genau dann, wenn ihre Wörterbuchdatei existiert. Optionen: `--langs es,fr`, `--force`, `--dry`. Unveränderte Quellen werden per Hash übersprungen. Nach Textänderungen in `de.json` oder `content/` erneut ausführen und das Ergebnis prüfen.
3. **Live-Übersetzung in jede Sprache:** Sprachwähler → „Weitere Sprachen“ → Claude API über den Proxy in `workers/translate/`. Nur sichtbar, wenn `NEXT_PUBLIC_TRANSLATE_ENDPOINT` (Repo-Variable `TRANSLATE_ENDPOINT`) gesetzt ist. Der Text geht erst nach aktiver Auswahl an den Proxy; die Datenschutzseite beschreibt das.

## Neue Texte oder Sprachen

- Neuer fester Text: in `de.json` und `en.json` ergänzen (gleiche Schlüssel), Ansichten in `src/views/` nutzen `getDict(lang)`. Fehlende Schlüssel in anderen Sprachen fallen auf Deutsch zurück.
- Neue Vorab-Sprache: Eintrag in `LANGUAGES` (`src/i18n/config.ts`) und `NAMES` (`scripts/translate.mjs`), Skript ausführen.
- Impressum und Datenschutz sind nur in der deutschen Fassung rechtlich maßgeblich; die übrigen Sprachen sind Lesehilfen.
- Rechts-nach-links-Sprachen (ar) setzen `dir="rtl"`. Das CSS nutzt teils physische Eigenschaften (`border-left`), dort ggf. nachziehen.

## Automatische Aktualisierung

`.github/workflows/translate.yml` läuft täglich (und manuell über „Run workflow“). Er übersetzt nur Quellen, die sich seit dem letzten Lauf geändert haben (Hash-Cache `src/i18n/.translation-cache.json`, ohne Änderung keine API-Aufrufe), baut die Seite zur Kontrolle und öffnet einen Pull Request `bot/translations`. Veröffentlicht wird nichts: nach dem Merge den Pages-Workflow manuell starten.

Einmalig nötig:
- Repository-Secret `ANTHROPIC_API_KEY` (Settings → Secrets and variables → Actions → **Secrets**), am besten ein eigener Key mit Ausgabenlimit.
- Settings → Actions → General → Workflow permissions: „Allow GitHub Actions to create and approve pull requests“ aktivieren.

Hinweise:
- Ein von `GITHUB_TOKEN` geöffneter PR löst die normalen PR-Checks nicht aus. Deshalb baut der Workflow selbst vor dem PR.
- Englisch wurde von Hand geschrieben. Eine vorhandene Datei ohne Cache-Eintrag wird beim ersten Lauf als aktuell übernommen („adopted“), danach wird auch Englisch bei Änderungen am Deutschen neu übersetzt.
- GitHub pausiert geplante Workflows, wenn das Repository 60 Tage lang inaktiv ist. Ein manueller Start oder ein Commit reaktiviert sie.
